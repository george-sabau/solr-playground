# Solr Playground: Master Blueprint & Rules

## 1. Project Context & Rules (General.md Logic)

This project is a high-performance UI layer sitting on top of the default Apache Solr Dashboard.

- **Core Principle:** Enhance, don't replicate. Focus on UI/UX features the default Solr Admin UI lacks, such as saved queries and visual boost sliders.
- **Safety First:** Never mutate data; this is for querying and analysis.
- **Introspection:** Always use the Luke API (`[core]/admin/luke?show=schema&wt=json`) to understand field types and flags.
- **Stack:** Next.js, Tailwind CSS, Shadcn UI, and Zustand for state management.

## 3. Persistent Change History

**Current Status:** Phase 1 done; local Solr showcase (Docker) available under `solr/`.

- **2024-05-22:** Initial architecture established. Decided on a "Sidecar UI" approach to avoid JVM deployment overhead.
- **Crucial Lesson:** Ensure Solr CORS policy is configured to allow requests from the app's port (usually localhost:3000).
- **2026-05-03:** Adopted a Next.js server-side proxy at `/api/solr/[...path]` so the browser never talks to Solr directly — **CORS on Solr is not required** for local dev when using this app. Base URL and optional Basic Auth are sent from the client store via `x-solr-base-url` / `x-solr-auth` headers.
- **2026-05-03:** Local showcase Solr runs as **one Docker container (Solr 9)** with two cores — `products` and `customers` — seeded from `solr/data/*.json`. The Next.js app stays on the host (`npm run dev`). One JVM / two cores is the normal Solr model; a second Solr container would only duplicate memory for this demo.
- **2026-05-03:** Added **`npm run dev:stack`** (Solr `docker compose up -d` + `next dev`) and **`npm run stop:stack`** (`docker compose down` + `kill-port 3000`) so the showcase stack can be started and stopped from the repo root.
- **2026-05-03:** `dev:stack` / `stop:stack` now run **`scripts/dev-stack.mjs`** and **`scripts/stop-stack.mjs`** so `docker` is found when missing from PATH (Docker Desktop default path on Windows, or **`DOCKER_EXE`**).
- **2026-05-03:** Docker discovery uses **`docker --version`** (not `docker version`) plus **`where.exe docker`** and extra Windows paths — `docker version` falsely failed when the engine was stopped.
